# 評価基準

## 必須指標

1. **完全復元率**: 元のUnicode文字列を完全に復元できた文書の割合。正規化がある場合は、正規化後の期待値も別途報告。
2. **Tokens per character (TPC)**: `token_count / Unicode code point count`。文字数の定義を全実験で統一。
3. **Encode / decode throughput**: 文字/秒と文書/秒。ウォームアップ後に複数回測り、中央値と分散を報告。
4. **Vocabulary utilization**: 評価セットで使われた異なるトークン数と未使用語彙比率。
5. **Unknown / fallback behavior**: 希少字、拡張漢字、異体字、欠損字形を含む試験。
6. **Linguistic coverage**: 事前に定義した機能語・熟語・句法パターンの境界が、どの程度期待通りになるかを人手確認付きで評価。
7. **Generalization**: 未見作品splitにおけるTPCと語彙品質。

## 実験ルール

- 文字単位、BPE 16k/32k/64k、漢文特化候補を同じコーパスsplitで比較。
- 少なくとも3回測定し、中央値を採用。環境情報とコミットSHAを記録。
- テスト作品を語彙選定や閾値調整に使わない。
- TPCだけで優劣を決めない。速度、語彙の言語学的妥当性、未知字処理を併記。
- トークナイザー単独では意味理解性能を証明できない。LLMを使う下流評価は別実験とする。

## 初期の受け入れ基準

- サンプルでCLIが成功し、JSONレポートが生成される。
- 期待する正規化ルールを明記し、サンプル文が100%復元される。
- 同一データ・同一設定から再現可能な成果物が生成される。
- データセットに出典・版・ライセンスの記録がある。
- 性能値は実測値のみを報告し、推定値と混同しない。
