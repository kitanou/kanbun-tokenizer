## 範囲と読み方

- 対象トークナイザー: `artifacts/baseline-wikisource/bpe-2000` と `bpe-16000`（ByteLevel BPE、14作品中12作品＝train split で学習。論語・呂氏春秋は未学習）。
- 分析対象テキスト: 学習に使っていない論語＋呂氏春秋（1,197行、137,212文字）。出現回数が少ない語は偏りが大きい。
- 各出現を次に分類する。**isolated** = 目標語がちょうど1トークン、**merged** = 目標語がより長いトークンに含まれる、**straddle** = 複数文字の目標語が2つ以上の完全なトークンに分かれる、**split** = 1文字がバイト断片に切られる。
- これは分割の記述であり、構文解析ではない。「merged」「isolated」は言語学的な良し悪しを意味しない。圧縮率だけから句法上の主張はしない（issue 04 の受入条件）。
- 評価セット（出典付き例文・注釈ガイドライン）は未作成。ここでの出現はコーパス上の文字列一致で、多義（例: 「之」が代名詞か助詞か、「以」が動詞か前置詞か）は区別していない。

## 観察

1. **語彙を増やすと機能語単体のトークンは減る**。16kでは「不」「之」「也」「而」の大半が隣の文字と融合し、単独トークンは1〜2割台。2kでは単独率が高い。トークン化の仕様（語彙サイズ）に強く依存する。
2. **頻出の結合は文脈語を含む**。「而不」「不可」「之也」「者也」「之所以」などが16kで独立の語彙になっている。これらは文字列の共起頻度で選ばれたもので、品詞や句法の単位とは限らない。
3. **稀な字はバイト断片に割れる**。「耶」（n=4）は2k・16kとも split（学習データに現れず、バイト級で分割）。「歟」は2kで split、16kでは単独トークン。16k時点でも、コーパスに現れない異体字・稀字は常に同様に分割される。ByteLevelで復元性は保たれるが、1文字が2〜3トークンになる。
4. **疑問の「乎」は16kでも約6割が単独**。残りは「者乎」「在乎」など前接語と結合する。

## 仮説（未検証）

- 機能語の単独トークン化を促す／結合を抑える方式（機能語を語彙に注入する、結合の対象から外す）が、下流タスクや汎化に効くかは不明。M3 のアブレーションで評価する。
- 稀字の split は、語彙に漢字全体を入れる（文字単位フォールバックを持つ）方式で改善できる可能性がある。
